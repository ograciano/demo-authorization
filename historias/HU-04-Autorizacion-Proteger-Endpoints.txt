HU-04 - Protección de endpoints mediante permisos

Como desarrollador backend,
quiero proteger endpoints usando permisos específicos,
para asegurar que solo usuarios autorizados puedan ejecutar operaciones sensibles.

Objetivo técnico:
Implementar validación de autorización en endpoints protegidos de un backend Java 17, utilizando roles/permisos y JWT previamente emitido por el servicio de autenticación.

Alcance funcional:
- Validar token JWT recibido en el header Authorization.
- Extraer usuario y roles desde el token o desde el contexto de seguridad.
- Validar permisos antes de ejecutar la operación protegida.
- Retornar HTTP 403 cuando el usuario no tenga permiso.
- Permitir acceso cuando el usuario tenga el permiso requerido.

Buenas prácticas esperadas:
- Usar Spring Security con filtros JWT.
- Centralizar la validación de seguridad.
- Usar anotaciones como @PreAuthorize cuando aplique.
- Evitar lógica de permisos duplicada en cada controller.
- Definir permisos claros por recurso y acción.
- Responder HTTP 401 para token ausente o inválido.
- Responder HTTP 403 para usuario autenticado sin permiso.
- No exponer detalles internos de seguridad.

Ejemplo de endpoint protegido:
GET /api/reports/{reportId}/download

Permiso requerido:
REPORT:DOWNLOAD

Headers:
Authorization: Bearer <jwt>

Ejemplo de solicitud permitida:
GET /api/reports/100/download
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.demo

Ejemplo de salida permitida HTTP 200:
{
  "reportId": 100,
  "fileName": "reporte-clientes.csv",
  "downloadUrl": "https://demo.local/files/reporte-clientes.csv"
}

Ejemplo de token ausente HTTP 401:
{
  "timestamp": "2026-05-13T10:45:00",
  "status": 401,
  "error": "Unauthorized",
  "message": "Token JWT requerido",
  "path": "/api/reports/100/download"
}

Ejemplo de permiso insuficiente HTTP 403:
{
  "timestamp": "2026-05-13T10:46:00",
  "status": 403,
  "error": "Forbidden",
  "message": "No cuenta con permisos para ejecutar esta operación",
  "path": "/api/reports/100/download"
}

## Requisitos de OpenAPI/Swagger Desde el Inicio
- La anotación @Operation debe documentar el propósito del endpoint y permisos requeridos.
- La anotación @ApiResponse debe documentar respuestas 200, 401, 403 con ejemplos.
- La anotación @SecurityRequirement(name="bearerAuth") indica que el endpoint requiere JWT válido.
- La anotación @SecurityScheme en OpenApiConfig debe estar configurada (type=HTTP, scheme=Bearer, format=JWT).
- El endpoint debe ser documentable en Swagger UI (/swagger-ui.html) con opción "Authorize" funcional.

Reglas de negocio:
- El token debe ser válido, no expirado y estar correctamente firmado.
- El usuario autenticado debe tener el permiso requerido.
- Un usuario autenticado sin permiso recibe HTTP 403.
- Una petición sin token o con token inválido recibe HTTP 401.
- El endpoint no debe ejecutar lógica de negocio si falla la autorización.

Criterios de aceptación:
1. Dado un token válido y permiso REPORT:DOWNLOAD, cuando se invoque el endpoint, entonces debe responder HTTP 200.
2. Dado un token ausente, cuando se invoque el endpoint, entonces debe responder HTTP 401.
3. Dado un token inválido o expirado, cuando se invoque el endpoint, entonces debe responder HTTP 401.
4. Dado un usuario autenticado sin permiso, cuando se invoque el endpoint, entonces debe responder HTTP 403.
5. La autorización debe ejecutarse antes de la lógica de negocio.

Sugerencia de estructura técnica:
- SecurityConfig
- JwtAuthenticationFilter
- JwtService
- CustomAccessDeniedHandler
- CustomAuthenticationEntryPoint
- PermissionEvaluator
- ReportController
- ReportService
